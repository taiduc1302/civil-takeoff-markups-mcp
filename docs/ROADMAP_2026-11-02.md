# Civil Takeoff Markups MCP — improvement roadmap

Updated: 2026-11-02. Source baseline: `main@675065edfd4f9ffd6b8435e3e8f8fe9cf4125e5a`.

## Mission

Build a **local-first, reviewable and verifiable** civil takeoff workflow which can propose geometry, create/read back genuine Bluebeam-native measurements when the current runtime exposes and proves a supported path, and safely reconcile the results with estimator-owned scope. This is **not** an automatic bid approval product.

## Current baseline and findings

- Existing: written six-step method, synthetic plan/profile PDF, JSON geometry built alongside the fixture, proposed `add_markup` payloads, external traceability register guidance, pure QA transition guard, municipal review validator and 8 municipal tests.
- **17 currently generated candidates**: 4 duct run lengths + 4 restoration polygons + 8 point shapes + 1 QA measurement. README/Data Policy historically describe 21 markups in the marked PDF. Establish whether these are two different historical stages before editing claims; do not quietly alter historical evidence.
- The geometry generator and markup derivation share source variables, so this is not an independent PDF vector-extraction demonstration.
- `validate_register.py` describes validation of a Comment string while the traceability contract says authoritative structured fields must live **outside** mutable Bluebeam measurement comments.
- `validate_register.py` accepts `SCALE_VERIFIED=N` in an otherwise complete row; `qa_state_transitions.py` validates only a proposed transition plus caller-provided actor, not the source, saved measurement, independent check, or human identity.
- `place_markups.py` emits JSON without connector transport or saved native quantity readback. Revu MCP creation, Count, and measurement intents must be tested against exact current point-version and exposed tools.
- No repository Actions workflow is needed to begin the offline improvements.
- Keep all real drawings, markups, BAX, employer codebooks, rates and client data outside this public repository.

## Mandatory safety and evidence rules

1. Independent scale *resolution* and *verification*; scale-dependent measurement without evidence cannot be QA checked.
2. A returned length only verifies the submitted path, not that the path follows the correct design feature. Render overlays and require independent checks.
3. No auto-promoted human decisions. `--actor human` is a test argument, **not authentication**.
4. Subject fields are informative; the external register carries stable IDs, file/revision hashes, lineages, status and evidence.
5. A static Circle is **not** a native Count. Count MCP support must be classified by actual Revu version and live availability, not described as universally impossible.
6. Never sum QA-only objects, unresolved matches, duplicate contributors, stale revisions, or unverified native measurement types.
7. Never assume exact source geometry from the same variables which generated a fixture: independent PDF readback must be separately tested.
8. No secrets, client documents, private tender data or proprietary drawing exports in the public repo.

## Definition of done

- All offline synthetic regression tests pass (no live dependencies).
- Updated documentation matches exact source-backed output.
- Unsupported Bluebeam operations fail closed; GUI-native fallback documented.
- Disposable real-Revu acceptance test receipts are retained **privately**, with redacted summaries only if publishable.
- Quantity totals are not marked estimate-ready without matching source authority, page/scale evidence, independent location checks, native measurement readback, duplicate exclusion and human decision.
- Changes are in small reviewable PRs with results/limitations.
